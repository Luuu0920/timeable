# 课表日历

一个只给自己用的课表 + 日程 App。把大学课表和个人计划（待办 / 健身 / 考试 / 活动）放在同一张周视图里。

**纯本地存储，没有后端、没有登录、没有账号，数据不上传。**
所有数据存在你手机的浏览器里，靠导出 JSON 备份来换机/换学期。

### 分享给别人用时，首次打开会发生什么

`seed.json` 是**示例性质**的：别人拿到链接第一次打开，会看到这份虚构的示例课表。
所以首启逻辑必须把话说清楚，否则对方只会一脸懵。当前行为：

| 场景 | 判定 | 表现 |
|---|---|---|
| 全新设备（本机无任何数据） | `firstOpen = true` | 弹首启说明弹层 |
| 已有数据的设备（含点过「清空」的） | `firstOpen = false` | 不弹，直接进 App |
| 拿不到 `seed.json`（断网等） | `firstOpen = true` 且数据为空 | 弹"真空白"版说明（先去设置学期 / 先去导入课表） |

`firstOpen` 的判据是**「启动时 localStorage 里一条数据都没有」**，在 `tryLoadSeed()` **之前**
取快照。**不要用「`data` 为空」当判据**，那会引入两个 bug：

1. `tryLoadSeed()` 载入 seed 后会 `persist()`，`data` 就不为空了 → 首启说明永远弹不出来；
2. 用户点「清空所有数据」后 `data` 也是空的 → 一刷新示例课表又自己冒出来。

> ⚠️ **课表更新传不到老朋友手机上。** 老朋友本地已有数据，改 `seed.json` 重新发布**不会**
> 更新他们的课表——这是刻意行为，否则会把朋友自己录的内容冲掉。要"改一次全体同步"就得上后端。

## 二、数据模型

核心原则：**只存规则，不存展开后的实例**。渲染时按"当前日期 + 教学周"即时计算该显示什么。

### 学期锚点

只存一个字段 `settings.termStart` = **第 1 周的星期一**。

教学周一律反算：`周次 = floor((该日期所在周一 − termStart) / 7) + 1`

这是整个设计的关键——"现在是第几周"永远只有一个真相来源，不存在两处数据互相矛盾的可能。改学期起始日 = 整体平移教学周，课表不用动。

### 课程

```js
{
  id, name, teacher, color,
  sessions: [{          // 一门课可有多个上课时段
    day: 1..7,          // 1=周一 ... 7=周日
    startNode, endNode, // 节次（存节次而非时间）
    startWeek, endWeek, // "第 1~16 周"
    weekType,           // all=每周 / odd=单周 / even=双周
    location, teacher
  }],
  overrides: [{         // 调课/补课，只影响某一天
    date, action,       // action: cancel=停课 / move=改时间 / add=补课
    startNode, endNode, location
  }]
}
```

**为什么存节次而不是时间？** 因为作息表可能改动（比如换季调整）。存节次的话，改一处 `settings.timeTable`，全课表时间自动跟着变；存时间的话，每门课都要改。

### 个人计划

```js
{
  id, name, type,        // type: todo=待办 / gym=健身 / exam=考试 / activity=活动
  date, endDate,         // endDate 仅用于跨天的一次性事件
  start, end, location, note,
  repeat: {
    mode,                // none=一次性 / weekly=每周 / biweekly=隔周
    days: [1,3,5],       // weekly/biweekly：星期几
    parity,              // biweekly：odd=单周 / even=双周
    until                // 重复截止日期，null = 一直重复
  },
  reminders: [15],       // 提前多少分钟提醒
  doneDays: ['2026-10-10']  // 仅待办：哪些天已完成
}
```

只支持你要的三种重复（每周 / 隔周 / 一次性），没有多余选项。

**待办（todo）** 是"备忘 + 待勾"类型，跟健身 / 考试 / 活动并列。两个设计要点：

1. **不占具体时段**——待办是"这一天要做的事"，不是"几点到几点"。编辑器里选「待办」会隐藏开始/结束时间，日历卡片上也不显示时间段。
2. **按天记录完成状态**——`doneDays` 存"哪几天勾完了"。这样**每周重复的待办可以这周勾了、下周还没勾**，不会一勾就把所有未来出现全部标成完成。
   - `doneDays = []` 表示都没完成；`['2026-10-10']` 表示这天完成了。
   - 兼容旧数据：`doneDays = true` 视为恒完成（读入时不会被改写）。
   - 用 `Core.isDoneOn(doneDays, dateKey)` 判断、`Core.toggleTodoDone(doneDays, dateKey)` 切换（纯函数，不原地改数组）。

### 存储

`localStorage` 单键存储整个数据集（`timetable.data.v1`）。个人数据量在几百条以内，同步读写最简单，也避免了 IndexedDB 的异步竞态——这对"能用、好改"更重要。

## 三·五、作息表（一天几节课）与节次自适应

**各校作息不同 —— 这是"用户自己的数据"，不是 App 的常量。**
所以「设置 → 上课时间表」里可以加/减一天几节课、逐节改时间；
周视图左侧的节次轴、以及日程卡片的落位，全部由 `data.settings.timeTable` 推出。

### 为什么会出现"第 11 节的课跑到第 1 节"

课程里存的是**节次号**（`startNode` / `endNode`），周视图却要按**具体时间**落位，
中间的桥梁是 `C.nodesToTime(timeTable, startNode, endNode)`：

```js
var s = tt[startNode - 1], e = tt[endNode - 1];
return { start: s ? s.start : '08:00', end: e ? e.end : '09:40' };  // ← 越界就回落成第 1 节
```

而默认 `DEFAULT_TIME_TABLE` 只有 **10 节**。用户录一门「第 11-13 节」的课，
节次号存得没错，但 `timeTable` 里取不到 → 回落成 `08:00-09:40`
→ 卡片被画到最上面，看起来就是"顺延成了第 1-3 节"。

### 修法：三层

1. **`core.fitTimeTable(data)`（纯函数）** —— 让作息表至少覆盖 `maxNodeUsed(data)` 节。
   补出来的节次带 `auto: true`，界面上提示"这是按你的作息节奏自动补的，请核对时间"。
   在 `migrate()`（读数据）和 `app.persist()`（写数据）各调一次，
   于是批量导入、手动编辑、恢复备份、清空重来都会自动对齐。
2. **`core.resizeTimeTable(data, n)`** —— 「一天几节课」的加减。
   **只动末尾**：从中间删一节会把它后面所有课程的"第几节"整体前移一位，
   那等于在悄悄改用户的课表，所以不做。下限受 `maxNodeUsed` 约束 ——
   减到会把已有的课弄丢时会被夹回去并给出提示。
3. **看板底边跟着作息表走** —— `renderWeek()` 里 `dayEnd = max(23, ceil(最大结束时间))`，上限 24:00。
   否则 22:40 才结束的晚课会溢出 `.daycol`。

补节的节奏由 `nextPeriod()` 推断：**步长取相邻节次间最小的开始间隔**
（自动跳过午休 / 晚饭那种大空档），时长沿用最后一节。
默认表最后一节是 19:55-20:40、最小开始间隔 55 分钟 → 补出来 20:50 / 21:45 / 22:40。
（若改用"最后一次间隔"135 分钟，就会补成 22:10 —— 被晚饭空档带跑，所以特意取 min。）

### ★ 顺带修掉的老坑：`DEFAULT_TIME_TABLE` 曾是浅拷贝共享

`emptyData()` 原本写 `timeTable: DEFAULT_TIME_TABLE.slice()` —— **浅拷贝**：
数组是新的，但每个 `{start,end}` 还是同一批对象。
后果：用户在设置页改第 1 节的时间，会顺着共享引用把**全局基准**一起改掉，
之后「清空所有数据」拿到的就不再是默认作息，而是他最后改过的那份。

现在统一走 `defaultTimeTable()`（深拷贝），`migrate()` 也会把读进来的作息表复制一份。
`core.test.js` 里有一条用例专门盯着这件事。

## 五、手机安装步骤

推荐走**发布成在线链接**的路子，因为它是唯一一个"不依赖电脑开机、不依赖数据线"的方案。App 本身是纯静态文件，数据仍然只存在你手机上（`localStorage`），服务器上只有代码，**你的课表不会上传**。

### 方案 A：发布成链接（推荐）

1. 让 WorkBuddy 把 `timetable` 目录发布为一个在线链接。
2. 手机浏览器打开该链接。
3. **Android（Chrome / Edge）**：右上角菜单 → 「添加到主屏幕」/「安装应用」。
   **iOS（Safari）**：底部「分享」→ 「添加到主屏幕」。
   > iOS 一定要用 Safari，且必须走"添加到主屏幕"，否则拿不到全屏独立窗口体验。
4. 回到桌面，点图标启动。此后即使断网也能用（Service Worker 已缓存）。

### 方案 B：本地文件（不联网，但麻烦）

1. 把整个 `timetable` 文件夹拷到手机（数据线 / 网盘 / 微信传文件）。
2. 用支持本地打开的浏览器打开 `index.html`（Android 的文件管理器一般可以直接选浏览器打开）。
   - ⚠️ iOS 对 `file://` 限制严格，`localStorage` 可能被隔离，**不建议**在 iOS 上走这条路。
3. 缺点：每次更新代码都要重传；`localStorage` 可能因浏览器清理策略丢失，**务必定期导出 JSON**。

### 方案 C：电脑开服务器，手机同 WiFi 访问

```bash
cd timetable
python -m http.server 8080
# 查电脑局域网 IP（Windows: ipconfig），手机浏览器访问 http://<电脑IP>:8080
```
只在调试时用——电脑一关机就没了。

## 五·五、怎么自己验收"朋友视角"

**为什么要专门讲**：你自己的设备已经有数据了，App 就**永远不会**给你弹首启说明、
也不会载入示例课表——这是刻意设计（不骚扰老用户）。
所以你打开链接看到的画面，**和朋友第一次打开看到的完全不是一回事**。

### ⚠️ 别用「设置 → 清空所有数据」来模拟

这是最容易踩的坑。清空之后 `localStorage` 里仍有一份**空数据**，
所以 `firstOpen` 判定为 `false`：

- **首启说明不会重新弹**（`tt.guided` 标记也还在）
- 而且它会**真的删掉你自己的课表**（要先导出 JSON 备份才能救）

### App 在本机只存两个键

| 键 | 含义 |
|---|---|
| `timetable.data.v1` | 全部数据（课程 + 计划 + 设置） |
| `tt.guided` | 「已经看过首启说明」的标记 |

**两个都删掉**才算"全新设备"。只删一个达不到效果。

### 方法一：电脑上最快（推荐）

开一个**无痕 / InPrivate 窗口**（Edge `Ctrl+Shift+N`，Chrome `Ctrl+Shift+N`），
粘贴线上链接。无痕窗口每次都是干净存储 → 直接就是朋友视角。

> 想看"清空之后"的状态，就点首启弹层里的「清空，我要录自己的」。
> 无痕窗口**不能**用来测「添加到主屏幕」（无痕模式不支持安装）。

### 方法二：手机上最真实

- **微信里打开**：微信内置浏览器有**独立存储**，第一次点开就等于朋友第一次点开。
  ⚠️ 只有一次机会，之后再点就变成"老用户"了（要重置得清微信缓存，很麻烦）。
- **无痕浏览**：iOS Safari「标签页 → 无痕 → +」；Android Chrome 右上角「新建无痕标签页」。
- **换一个浏览器**：手机上换个平时不用的浏览器打开同一个链接。

### 方法三：彻底重置某个浏览器（能测"装到桌面"）

在**普通窗口**里删站点数据，然后刷新：

| 平台 | 操作 |
|---|---|
| 电脑 Edge/Chrome | 地址栏左侧图标 →「Cookie 和网站数据」→ 删除；或 F12 → Application → Local Storage → 删掉那两个键 |
| iOS Safari | 设置 → Safari → 高级 → 网站数据 → 找到该域名 → 删除 |
| Android Chrome | 设置 → 网站设置 → 查看所有网站 → 找到该域名 → 清除并重置 |

删完刷新，就是全新设备：会弹首启说明 + 载入虚构示例课表。

### 朋友视角该核对哪几件事

1. 弹层是否出现、**文案是否说得清**（"虚构的演示数据，不是任何人的真实课表"）
2. 示例课表长得**像不像一个能用的 App**（周视图有课、有颜色）
3. 「清空，我要录自己的」→ 是否真清空、是否跳到课表页
4. 底部「说明」页能否打开、**目录能否跳转**、「复制这段话」能否真的复制
   （`http://<IP>` 这种非安全上下文里 `navigator.clipboard` 不可用，会走 `execCommand` 兜底）
5. 照「说明」页走一遍批量粘贴，能否录入自己的课
6. 加到桌面后打开，**是否没有地址栏**（有地址栏 = 加成了书签）
7. 顺手确认：`https://<链接>/seed.json` 打开是那份虚构示例，**不是你的课表**

> 想偷懒的话：`shots/help-01-firstrun.png`（首启弹层）、`shots/help-02-week-sample.png`
> （示例课表周视图）、`shots/help-03-help-top.png`（说明页顶部 + 目录）、
> `shots/help-05-ai-prompt.png`（「让 AI 帮你转格式」那段）都已拍好。

## 六、导入课表

### WakeUp 课程表

在 WakeUp App 里：**右上角分享 → 导出为备份**，得到一个 `.wakeup_schedule` 文件。
然后在「课表 → 导入」里选这个文件。

> 注意：`.wakeup_schedule` 是**纯文本 JSON Lines 格式**（每行一个 JSON 对象，共 5 段），**不是 ZIP 压缩包**。5 段依次是：节次元信息、节次时间表、课表元信息（含学期起始日与总周数）、课程表、上课安排表。
> 导入时会自动读取学期起始日、总周数、节次时间表、教室、教师、单双周。

### ICS

系统日历 / Google 日历 / 苹果日历导出的 `.ics` 都能导入。「设置 → 导入 ICS」。

### 批量粘贴（兜底，也最常用）

「课表 → 批量粘贴录入」，每行一门课：

```
高等数学 周一 1-2节 1-16周 教三201
大学英语 周三 3-4节 单周 外语楼A101
体育 周五 5-6节 1-18周 操场
```

支持：`周X` / `星期X`、`N节` 或 `N-M节`、`单周` / `双周`、`第N周` 或 `N-M周`。
点「先检查一下」会先预览识别结果并列出无法识别的行。

## 七、备份与迁移

**换手机 / 换学期前，一定要导出一次。**

- **导出 JSON**（设置页）：完整数据，下次用「恢复 JSON 备份」一键还原。**这是唯一的完整备份方式。**
- **导出 ICS**（设置页）：可导入系统日历 / Google / 苹果日历，用于在别的日历 App 里看。注意 ICS 是"展开后"的格式，导回来会变成一个个独立事件（重复规则会丢），所以**迁移请用 JSON，ICS 只用于对外分享**。

## 八、关于提醒（通知功能已移除）

**结论：本 App 不弹系统通知。** 曾按网页通知实现过（设置页授权 + App 内每 30 秒轮询），
但网页通知有两个绕不开的硬伤：① App 被杀掉后定时器也停了，**该响的时候不响**；
② 权限一旦授予，**网页无法替用户关闭**，只能在设置里留一篇"怎么关"的教程——
对个人小工具是净负担。故整体移除（设置页「提醒」区块、计划编辑器的「提前提醒」、
轮询逻辑全部删除；数据模型里的 `reminders` 字段保留仅为兼容旧备份，不再读取）。

**要提醒就一条路，而且更可靠**：「设置 → 导出 ICS 日历」把课表导进手机自带日历
（iOS 日历 / Google 日历），让系统日历负责提醒——那才是系统级、杀不掉的。
App 内的考试倒计时横幅、待办勾选、按周重复不受影响。

## 十、已知限制

- **不做系统通知**：网页提醒不可靠（App 被关就停），已整体移除；要提醒请「导出 ICS」进系统日历（见第八节）。
- **桌面小组件没做**：需要原生能力，PWA 做不了；用"添加到主屏幕 + 日视图"替代。
- **`showWeekend` 关闭时**，周视图只显示周一到周五；周六日的课程仍存在数据里，只是不显示。
- 数据存在浏览器里。**清理浏览器数据、卸载浏览器会导致数据丢失**——请定期导出 JSON。
